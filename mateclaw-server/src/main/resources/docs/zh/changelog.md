# 3.0.0-SNAPSHOT：执行架构升级

开发快照，尚未发布正式版本。

## 自 2.3.0 以来的累计更新

3.0.0-SNAPSHOT 同时收录原 2.4.0 开发周期的更新；2.4.0 未单独作为正式发行版发布。以下按能力归类，避免把架构迁移前的功能遗漏。

### 工作空间与会话

- 成员文件隔离为可选严格沙箱模式，开启 `MATECLAW_WORKSPACE_SANDBOX_MEMBER_ISOLATION_ENABLED=true` 后按已认证用户和工作空间划定文件根目录；身份缺失即拒绝访问，不回退到共享目录。当前仅开放六个经审查的内置文件/代码工具；DSH、MCP/plugin 工具、共享技能脚本和未认证渠道身份不可用。它与个人记忆文件的共享回退是不同机制。 (#644).
- 持久渠道会话过期查询上下文清理，避免旧请求影响新任务。上传图片从会话存储解析，目录附件保留目录信息并校验上传边界。
- 员工创建时兼容推理块后的 JSON；显式关闭工具的员工不再因通用能力被重新赋予工具（#648、#655）。

### 结构化决策与目标、计划、团队

- 新增有界、类型化的 Choice / Boolean / Score 决策管线及持久审计，支持 OFF / SHADOW / ACTIVE 和场景覆盖。默认 SHADOW，建议不能绕过领域硬约束。
- Goal 续跑决策、计划员工路由、团队 worker 结果判断共用结构化决策基础；结果与状态在领域事务中提交，延迟结果经身份与 fence 校验。
- 增强路由上下文、worker 输出契约、委派步骤结果校验和有界 Goal 恢复；记录已应用的后续执行抑制，保留原完成验收门。

### 模型与 DeepSeek Harness

- DSH 迁移至 SDK 运行时，新增锁定版本与受控升级；失败健康检查会失效，损坏配置仍可编辑修复（#650）。
- 模型探测检查已完成响应的有效性，不把只有连接或空响应误判为成功（#658）。

### 朗读、聊天与工具展示

- 恢复 Edge 和 DashScope 朗读，支持供应商音色列表、选择与试听（#646）。
- MCP 结构化结果支持专用工具展示，并放在最终回答下方；普通工具结果不再自动混进最终回答正文（#651、#656、#661）。

### 渠道与数据运维

- 飞书 WebSocket readiness 与资源生命周期由应用管理，关闭和重连释放所属资源（#659）。
- 不支持的 webhook 渠道在写入配置前拒绝，避免保存无法运行的配置（#654）。
- Flyway 校验失败默认拒绝启动，历史修复必须显式选择，保留备份与恢复指导（#657）。
- 增加商业版概览与入口；这不意味着开源版包含商业模块。

## 平台与执行核心

Java 21，Spring Boot 4.1.1，Spring AI 2.0.1，AgentScope Java 2.0.4。移除 Spring AI Alibaba starter 和 Graph 依赖。AgentScope 驱动普通 ReAct 和 Plan-Execute 单步内部的推理、工具、观察循环；整体计划调度、Goal 预算与验收、团队协作仍由 MateClaw 管理。

工具批次经 ApplicationGuardedToolkit 转交应用执行器，继续执行审批、工作空间权限、审计与取消策略。模型请求走现有 Spring AI/provider 适配；应用继续负责 SSE、历史记录及持久化。

## 模型、工具与恢复

- 原生 DashScope 聊天与 Embedding 适配替代 Alibaba AI 集成，保留原生语音 SDK。
- OpenAI/Anthropic 适配保留推理、媒体、缓存和用量；取消先终止所属 HTTP 调用，取消后不继续备用模型。
- MCP SDK 0.18.3：保留调用 ID、结构化结果和协议错误，应用内部执行能力不写入网络元数据。
- Goal 工具检查点在副作用前持久化执行身份；结果不确定时阻止盲目重放，保留审批恢复和会话隔离。
- MyBatis Plus 3.5.17 使用 Spring Boot 4 starter；保留 JSON 字符串 ID 与已有会话数据契约。
- 技能包二进制文件处理和内置文档镜像同步加固。

## 升级与验证

升级前停止旧进程并备份数据库、workspace、插件及配置。使用 Java 21 构建，检查第三方插件与新版依赖的兼容性；恢复旧版本时使用升级前备份，不能把升级后的数据库降级兼容视为已验证。

本轮完成 Maven reactor、前端构建、PostgreSQL/MySQL 迁移与事务分页、工具审批/取消、进程崩溃恢复及六小时持续运行验证。Kingbase 实机验证尚未覆盖。前端交互接口保持兼容，本轮没有重写聊天 UI。
